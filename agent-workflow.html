Agent workflow

A Triage-coordinated team turns one GitHub issue into a tested static HTML prototype, then hands it to a maintainer for review and merge.

Red coordination Gold decisions Blue implementation Green verification

Start with Triage

Triage owns the issue end to end. It checks the existing use cases, classifies the request, chooses an existing slug or proposes a new one, and invokes specialists with the outputs of earlier stages.

How work is handed over

  1. Triage gives each specialist the issue, classification, target path, and preceding handoff.
  2. Specialists return a status and evidence; they do not silently impersonate one another.
  3. Developer leaves changes in the shared workspace for Tester, not as a text-only summary.
  4. Deployment publishes the exact artifact validated by Tester.

What stops the run

  1. Ambiguous target, multiple matches, or work outside static HTML.
  2. An unresolved Analyst question or PM blocked/defer.
  3. Figma required but no verified design handoff exists.
  4. A Tester failure, unmet acceptance criterion, or failed Pages artifact check.

Specialist roles

Business Analyst

Finds actors and flows, identifies existing behavior to preserve, and writes observable acceptance criteria.

ready or blocked

UX Designer

Defines desktop and narrow layouts, controls, copy, keyboard behavior, and empty/error/success states.

wireframe or verified Figma

Product Manager

Protects scope before implementation, then compares the agreed scope with test evidence before shipping.

ready/defer/blocked · ship/hold

Architect

Turns approved scope and UX into a minimal static implementation plan without backend or build tooling.

scoped plan

Developer

Changes only use-case/<slug>/, records design status, and leaves the implementation in the shared workspace.

index + assets

Tester

Runs the real page locally and checks primary and edge flows, focus, responsive layouts, assets, and regressions.

pass/fail/blocked

Deployment

Builds and inspects the Pages artifact, then commits and opens or updates exactly one implementation PR.

PR ready for review

Maintainer

The only approval and merge role. A merged PR on main triggers GitHub Actions publication.

review / merge

Decision gates

Scope gate

PM uses the Analyst and UX handoffs to set must-haves and exclusions. Human review or Figma requirements are never silently waived.

Test gate

Tester reports evidence by numbered criterion. One targeted Developer-to-Tester fix cycle is allowed after implementation.

Delivery gate

PM can ship only with all must-haves and core evidence. Deployment must validate the same workspace that Tester checked.
